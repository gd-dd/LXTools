# 网络、公开下载与登录恢复

当前商店的工具架、Max工具集、LXGit和LXMaxAnimation都来自公开GitHub Release。普通用户可以不登录GitHub下载工具架、刷新商店和安装工具。登录是可选功能，不能把作者账号能访问当作所有用户都能访问的证明。

工具架启动先显示已有工具和缓存。后台检查、下载、应用分开；“仅手动检查”模式启动不联网。商店读取作者发布的静态索引，完整仓库扫描属于作者维护流程。

## 登录失效后的行为（0.0.7）

- GitHub API确实拒绝当前账户凭据并返回401时，工具架清理对应失效会话，显示原因和“重新登录”按钮。点击按钮进入账户设置，再通过GitHub设备授权流程登录。
- 公开下载和版本检查会尝试匿名继续一次。匿名请求仍检查真实Release、固定标签提交、源码清单、附件SHA-256和包内文件，失败不会冒充安装成功。
- 断网、代理连接失败、超时、403资源权限/限流及429不会自动退出账户。后台检查不会自动弹浏览器，也不会不断要求重新授权。
- 较早请求的失效响应不会清掉后来登录的新会话。登录码仍有效时，网络短暂失败继续等待同一次授权。
- 浏览器已授权但本机保存失败时，提供重试保存入口，复用本次授权结果；不会要求为同一次本地保存问题再次授权。保存成功前不要把它当成已持久登录。
- 本机凭据无法解密或损坏时会显示具体提示，保留原文件供用户主动处理。失效凭据无法删除时，使用只绑定该旧文件的失效标记；若配置目录连标记也无法写入，会明确提示无法持久退出，不声称已清除成功。

登录信息受Windows当前用户加密保护。复制到其他电脑/Windows账户不保证可解密。GitHub可能撤销或使凭据过期，客户端不能恢复已撤销的凭据。本版保留服务实际返回的过期/刷新元数据，**尚未实现自动刷新令牌**，不承诺永久有效；无刷新凭据时需重新授权。

## 下载中断的恢复（0.0.8）

安装前核对版本只请求40字节提交号，不再为这个步骤下载完整提交差异。Release、固定标签提交、源码清单、附件大小和SHA-256仍逐项核对。

GET请求遇到响应提前结束、连接重置等传输中断时，最多尝试3次（含首次），每次重新获取完整响应；界面显示失败阶段和尝试次数。原始资源域传输失败时，可使用同一固定提交的GitHub API备用源，总尝试数仍有限。工具附件重试重新获取下载地址，不混用半段数据。这是完整重取，不是断点续传。

HTTP权限/限流错误、证书验证失败和真正的摘要不匹配不作为普通断流盲目重试。登录授权POST不进入GET重试流程；网络失败保留账户。连续失败时显示中文原因，旧目录、旧安装和配置保持，之后仍可主动重试。

0.0.7及更早版本出现`IncompleteRead`时，可以再次点击“安装选中版本”重新获取；无需为这类错误卸载工具或重新登录。自动恢复在升级0.0.8后生效。某台机器的网络持续不可达时，有限重试仍可能失败，需处理对应网络或代理问题。

## 根据错误排查

| 提示 | 含义 | 处理 |
| --- | --- | --- |
| IncompleteRead / 响应未完整接收 | 读取的内容少于本次HTTP响应声明的长度 | 0.0.8有限自动重取；失败后按提示检查网络或代理并重试，账户与旧安装保持 |
| WinError10061 / 连接被拒绝 | 连接尚未获得HTTP响应，可能是代理端口或目标服务拒绝连接 | 检查代理进程是否运行、软件/系统代理端口是否一致；恢复网络后重试。不要仅凭这个错误反复登出登录 |
| HTTP401且请求携带账户凭据 | GitHub拒绝本次账户凭据 | 使用“重新登录”；公开操作可先匿名继续 |
| HTTP403且剩余额度为0，或HTTP429 | 服务限流 | 按提示等待，不必为此退出账户 |
| 其他HTTP403 | 可能是资源权限、组织策略、临时限流或下载地址问题 | 保留HTTP状态与服务域名；不能直接认定账户过期或盲目重登 |
| HTTP404 | 版本/文件不存在，或当前账号不可见 | 先刷新商店，核对公开Release；不要改成下载未知镜像 |
| 超时、DNS或安全连接失败 | 网络、代理、解析或TLS链路异常 | 检查对应网络环节，账户保持 |
| WinError5 / 拒绝访问本地目录 | Windows文件权限、文件占用或安全软件拦截 | 使用本人可写的安装目录，检查程序目录、其父目录和配置目录权限 |

正常下载涉及`github.com`、`api.github.com`、`raw.githubusercontent.com`和`release-assets.githubusercontent.com`。网页可打开不代表所有下载域名都可连接。软件不会自动关闭系统代理、防火墙或安全软件。

正式安装器按用户安装，不强制管理员权限。工具包位于程序旁的`tools`目录，自更新需要写入程序目录及其父目录以保存备份；便携配置还需要其指定profile可写。当前安装包没有数字签名，Windows首开信任提示与GitHub登录属于不同问题；不应关闭系统保护来诊断登录。

## 下载与问题反馈

从[正式发布页](https://github.com/gd-dd/LXTools/releases/latest)下载安装器或`LXTool-windows-x64.zip`，同时核对同版本`SHA256SUMS.txt`。不要只下载源码ZIP作为Windows客户端。

遇到问题时记录：工具架版本、失败阶段（商店/工具下载/自更新/登录）、错误码与域名、是否使用代理、是否仍能使用已装工具。不要分享token、设备授权码或带签名查询参数的临时下载链接。

本机检查通过只代表检查时的机器和网络，不能代替其他用户的网络或Windows策略验收。
