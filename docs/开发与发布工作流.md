# 开发与发布工作流

| 入口 | 用途 |
|---|---|
| `E:\project\LXTools\LXTools\start-dev.bat`（start.bat 同入口） | 源码开发客户端，外壳显示 0.0.0 |
| `E:\Ruanjian\LXTools\LXTool.exe` | 已发布的正式客户端，用户视角 |

两版统一使用“发现工具 / 我的工具 / 设置与更新”。开发版在发现工具中额外提供 `0.0.0 · GitHub 最新分支`；没有“本地工具开发”或本地源码预览入口。

## 工具开发

1. 在工具自己的仓库修改、构建并维护完整 .lxtool 清单。
2. 提交、推送到 GitHub 默认分支。
3. 开发客户端“发现工具 → 扫描作者仓库 → 工具详情 → 0.0.0 → 安装/更新”。
4. 从“我的工具”打开当前选择的版本，可切回 Release，也可卸载。

0.0.0 来自 GitHub，不是未推送的本机代码。扫描固定 commit，文件下载不跨提交；新提交通过更新快照获取，不新增永久版本。正式 Release 保留，不被快照覆盖。下载失败保留旧安装。

Git 忽略的 EXE/DLL/PYD 仅能从 manifest 原始版本对应 Release 补齐，且 SHA-256 必须与分支清单一致。源码新改动所需的新编译文件必须有可取得且匹配的产物，不能随便拿旧二进制代替。

## 工具架开发

双击 start-dev.bat，修改 src 源码，保存稳定约两秒后自动重建窗口。下载和弹窗期间延后；语法错误先提示修复。此热重载只针对工具架，不监听、不拉取本地工具仓库。

开发配置在 runtime/development/profile；正式配置在 %LOCALAPPDATA%/LXTool。开发外壳不接收正式自更新，正式 EXE 不接受开发模式开关。两版工具操作流程一致，工具来源差异仅为 0.0.0。

既有 tools/3dmaxScript、tools/LXGit 目录连接保留源码但不用于本地预览；不要递归清空这些连接。工具文件不提交进工具架仓库。

## 正式发布

开发验收 → 项目测试 → 确定正式版本 → 编译与摘要刷新 → 同一源码提交、标签和 Release 附件 → 用户客户端更新。

普通修复、图标修改、测试重试和打包不自动递增版本。正式首次版本 0.0.1，后续按发布递增。不得覆盖已发布同版本。用户明确授权后才进行提交、推送和发布。

工具架构建使用 build-installer.ps1。dist 是未发布验收产物；Ruanjian 中的客户端始终使用公开 Release，不把验收包覆盖进去。

本项目约定固化在 lx-tools-workflow Skill；具体工具格式与发行校验由 lx-tool-creator Skill 维护。
