# 工具分发约定（实现目标）

目录清单使用 `catalog/catalog.schema.json`，由目录源统一维护工具名称、分类和仓库；用户本机保存认证绑定、安装记录和项目绑定。清单不得包含令牌、任意脚本或绝对安装路径。

工具 ID 在目录内唯一，名称可以修改，ID 不随版本变化。同步目录不能覆盖本地安装状态或自动删除已安装工具；远端删除的条目应标记来源已移除。重复 ID、未知 schemaVersion 或不合法条目使此次导入整体失败，并保留原目录。

每个 Release 的 tag 表示发布版本，附件 ID 和 SHA-256 表示具体安装包。版本列表使用 Release 发布时间排序，不将字符串大小比较当成版本先后；固定版本不会自动升级。预发布默认隐藏，可明确选择。

分发附件为 ZIP，可通过 assetPattern（文件名通配符）筛选平台附件。没有匹配附件时提示发布方补充；多个附件时让用户明确选择，不随意取第一个。

下载、解压、安装记录提交分阶段执行。校验失败、下载中断或写盘失败不改变旧版本。远端没有可用哈希时明确标识未经远端哈希验证，不声称已验证发布者身份。

`integration` 表示工具声明的集成类型，不表示客户端已经实现该适配器。未支持的类型允许缓存和查看说明，但不能显示已安装到宿主。具体目录布局和宿主适配必须依据实际工具样本确定。

本机版本选择与宿主激活绑定是两个独立状态。未接入宿主时只显示本地选择；接入后按宿主版本或 Unity 项目分别维护绑定。

客户端自更新使用单独的仓库和发行附件配置；配置缺失时显示未配置，不将任何工具仓库当作客户端更新源。构建工作流准备和向 GitHub 发布是两个动作，发布需有对应的授权和真实仓库。
