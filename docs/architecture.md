# 实现方案草案

## 已确定

首版只支持 Windows。客户端本身和工具均存于 GitHub，具体仓库尚未指定。架构同时支持公开与私有仓库，并允许混合使用；先打通公开仓库流程，再接入私有仓库认证。

## 模块

1. 工具目录：读取清单，按 3ds Max、Unity、通用工具分类展示。
2. GitHub 访问层：获取目录、Release 元数据和附件；身份认证独立封装。
3. 包管理：下载到临时目录，校验哈希，安全解压，再登记已安装版本。
4. 版本管理：按工具 ID 和版本分别存储，保留历史版本；失败不覆盖当前可用版本。
5. 宿主适配：独立处理 3ds Max 脚本/插件、Unity 项目包和独立程序。
6. 客户端更新：单独检查自身 Release，退出后由更新程序或安装器完成替换。

## 版本切换语义

缓存版本与激活版本分离。Unity 按项目记录工具版本，不能让一个全局开关影响所有项目；3ds Max 按宿主版本和安装目标记录绑定。涉及占用文件时要求关闭宿主或下次启动生效。更新前保存绑定和必要备份，失败恢复原绑定。

固定版本的项目默认只提示更新，不自动迁移。工具版本需声明适用的宿主版本，兼容性未知时明确展示未知。

## GitHub 分发

客户端仓库管理客户端源码、构建流程和安装包；目录清单记录工具仓库及分发方式。工具可以独立仓库发布，避免所有工具被迫一起升级。

以明确的 Release tag 与附件确定版本，不将浮动分支当作可复现版本。只有源码 tag 而没有安装包的工具，需要单独定义分发规则。

公开资源允许匿名访问；私有资源要求用户有仓库访问权并提供适当凭据。凭据保存在 Windows 凭据存储中，不放入目录清单、日志或 Git。工具下载只请求必要读取权限。

权限撤销阻止后续访问，不能自动收回已经下载的文件。客户端仓库与工具仓库可分别设置公开或私有。

## 仓库访问与认证边界

- 目录源、工具源、客户端更新源分别配置，统一调用 GitHub 访问层。
- 每个源包含仓库所有者、仓库名及认证策略（匿名或指定凭据引用）。引用只是本机凭据的标识，不包含令牌本身；共享清单不得指定密钥。
- 公开源默认匿名访问，可选择使用凭据；私有源由用户在本机绑定有访问权限的凭据。多个仓库可以复用凭据，也可以分别绑定。
- 凭据模块负责存取、替换与移除凭据，访问层负责附加认证信息；安装模块和宿主适配器不接触令牌。
- 私有附件通过支持认证的 Release asset 接口下载。重定向到下载地址时不向其他主机转发 GitHub 凭据。
- 访问层区分网络故障、凭据失效、权限不足和限流。无法判定仓库是否存在或无权访问时展示两种可能，不直接标记工具已下架。
- 认证失败不删除已缓存工具、不修改项目绑定。切换账号时刷新远端目录权限状态，私有目录缓存与账号绑定。
- 验收覆盖匿名公开源、授权私有源、混合目录，以及凭据失效后仍保留已安装版本的情形。

## 首版验收目标

- 从真实目录源展示工具及可安装版本。
- 成功下载并校验一个真实工具包，网络失败不损坏已有版本。
- 同时保留两个版本并可靠切换；记录版本与实际绑定一致。
- 先打通一种工具形态，再扩展其他宿主适配。
- 展示客户端可用更新并通过安装器完成升级。

## 待定
